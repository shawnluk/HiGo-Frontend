## 三、注册与资料页邮箱

### 1. 注册页（`src/login/login.vue`）

- 在「手机号（可选）」上方新增「邮箱（可选）」输入行，`maxlength=128`。
- 提交前校验非空邮箱的基础格式；为空则不发该字段。
- 注册请求参数扩展为 `{ username, password, phone, email }`。

### 2. 登录缓存（`api/modules/auth.js`）

- 登录返回的 `phone` / `email` 位于 `users` 表顶层，`profile` 来自 `user_profiles`。
- `persistLogin` 在写入 `userInfo` 时把顶层 `phone` / `email` 合并进 `profile`，供资料页直接读取。

### 3. 后端

- 注册：邮箱可选；非空时校验 `^[^\s@]+@[^\s@]+\.[^\s@]+$` 且 ≤128 字符；重复返回 409「邮箱已被注册」。
- 登录：返回 `email`。
- 资料更新：支持 `email` 部分更新，空字符串表示清空。

## 四、性别与生日交互

### 1. 性别重置（`src/user-profile/user-profile.vue`）

- 性别枚举：`0=保密`、`1=男`、`2=女`；新增「保密」选项，修复此前无法重置的问题。
- `formatGender(0)` 显示「保密」而非「暂无」。

### 2. 性别弹窗

- 由原生 `uni.showActionSheet` 改为与项目一致的自定义白底圆角弹窗：
  - 选项行、选中高亮、右侧 `checkmarkempty`；
  - 底部「取消」按钮；
  - 遮罩点击关闭。

### 3. 可复用日期弹窗（`components/date-picker-modal.vue`）

- 通用 API：`:visible` / `v-model:visible`、`:value`、`:title`、`:start`、`:end`，事件 `confirm` / `cancel`。
- 年 / 月 / 日三列 `picker-view`，按年月动态计算天数，月切换自动收敛日期。
- 样式沿用性别弹窗的白底圆角卡片；遮罩使用 `overflow-y:auto` + 卡片 `margin:auto`，H5 空间不足时可滚动、不再上下偏移。

### 4. H5 吸附错位修复

- 现象：滚轮停止后停在 15 日下半部分 / 16 日上半部分。
- 原因：H5 `picker-view` 吸附步长取指示器实测高度，而行高被写死为 `44px`；弹窗打开时的 `scale` 动画会让挂载测量得到约 41.36px，步长与行高不一致并累积误差。
- 修复：
  - 打开动画去掉 `scale`，仅保留透明度；
  - H5 端行高不写死，跟随 `--picker-view-column-indicator-height`；小程序 / App 保留 `44px`。

### 5. 生日边界

- 后端要求生日「必须早于今天」，前端选择器上限改为昨天（`latestBirthday`）。
- 弹窗内部新增 `clampDate`：默认选中值与确认值都会收敛到 `[start, end]`，避免空值打开时默认落到今天而提交被拒。

## 五、草稿式编辑与一次性提交

### 1. 状态设计（`src/user-profile/user-profile.vue`）

| 字段 | 作用 |
| --- | --- |
| `draft` | 未提交的文本字段草稿（nickname / phone / email / gender / birthday） |
| `pendingAvatarPath` | 裁剪后的头像本地路径，仅本地预览 |
| `pendingAvatarUrl` | 已上传 COS 但资料未提交成功的头像 URL，重试复用 |
| `submitting` | 提交中状态，防重复点击 |
| `draftOwnerId` | 创建草稿时的 `userId`，用于识别退出 / 换号 |

- `viewInfo = { ...userInfo, ...draft }`：页面所有展示统一读取合并视图，实现草稿即时预览。
- `displayAvatarUrl`：本地裁剪图 → 待提交 URL → 已保存头像 → 默认头像。
- `hasDraft`：控制底部操作栏显隐及页面底部留白。

### 2. 编辑行为

- 昵称 / 手机号 / 邮箱 / 性别 / 生日编辑只调用 `setDraftField`，不再发起请求。
- 草稿值与已保存值归一化后比较：一致时自动移出草稿，全部改回原值时底栏自动消失。
- 「取消修改」调用 `resetDraft`，整体还原为已保存资料。

### 3. 头像

- 裁剪完成只更新本地预览，并提示「头像已更新，提交后生效」。
- 重新裁剪会覆盖本地预览并作废上一次已上传的 URL。
- 只有点击「确认提交」才上传 COS。

### 4. 提交过程（`submitDraft`）

1. 校验草稿字段（复用 `validateField`）。
2. 若存在待上传头像，先调用 `uploadAvatar` 取得 URL；失败则保留草稿与预览，不发起资料请求。
3. 组装 payload：`{ ...draft }` + 可选 `avatar`，未修改字段不出现。
4. 只发一次 `POST /api/v1/user/profile`。
5. 成功后合并后端返回值（兼容 `{ user_id, phone, email, profile }` 与 mock 回显），写入 `uni.setStorageSync('userInfo', ...)`，清空草稿。
6. 失败保留草稿；已上传头像复用 `pendingAvatarUrl`，重试不重复上传。

### 5. 页面生命周期

- `onShow`：有草稿时不重新读缓存；仅当 storage 中 `userId` 与 `draftOwnerId` 不一致（退出 / 换号）时清空草稿并重新加载。
- 草稿仅存于页面内存，刷新或关闭页面即丢失，未做离开拦截。

## 六、后端两阶段校验（`src/services/user-service.js`）

原逻辑「边校验边写库」：手机号写库后邮箱校验失败，会留下部分生效的数据。

现改为两阶段：

1. **第一阶段（只校验 / 查重）**
   - `phone`：非空须匹配 `^1[3-9]\d{9}$`，且不得被其他账号占用；
   - `email`：非空须格式正确且 ≤128 字符，且不得被其他账号占用；
   - `nickname`：非空、1-20 字符、仅中文/字母/数字/下划线/连字符；
   - `avatar`：URL 或图片数据校验；
   - `birthday`：`YYYY-MM-DD` 真实日期且早于今天；
   - `gender`：0 / 1 / 2。
2. **第二阶段（统一写库）**
   - `UPDATE_USER_PHONE`、`UPDATE_USER_EMAIL`、`user_profiles` 动态 SET。

任一项校验失败直接返回 400 / 409，不会产生部分写入。

昵称上限同步调整为 **1-20 字符**：后端常量、JSDoc、接口文档与前端 `NICKNAME_MAX_LENGTH`、输入框 `maxlength` 一致。

## 七、校验提示

### 1. toast 被弹窗遮挡

- 原因：uni-app H5 toast 层级为 `z-index: 999`，编辑弹窗遮罩为 `1000`。
- 修复：编辑 / 性别弹窗遮罩改为 `z-index: 990`，仍高于底部草稿栏（900），toast 可正常显示。

### 2. 弹窗内常驻提示

- 新增 `editError`，昵称 / 手机号 / 邮箱校验失败时在输入框下方显示红字，输入时自动清除。
- 避免 toast 1.5 秒消失后用户看不到错误原因。

### 3. 前端校验规则（对齐 `docs/用户资料修改接口.md`）

| 字段 | 规则 | 提示文案 |
| --- | --- | --- |
| 昵称 | 非空、1-20 字符、仅中文/字母/数字/下划线/连字符 | 昵称不能为空 / 昵称长度需为 1-20 个字符 / 昵称只能包含中文、字母、数字、下划线和连字符 |
| 手机号 | 非空时匹配 `^1[3-9]\d{9}$`；允许留空清除 | 手机号格式不正确 |
| 邮箱 | 非空时格式正确且 ≤128 字符；允许留空清除 | 邮箱格式不正确 |
| 生日 | `YYYY-MM-DD`、真实日期、早于今天 | 生日格式应为 YYYY-MM-DD / 生日不是有效日期 / 生日必须早于今天 |
| 性别 | 0 / 1 / 2 | 性别取值应为 0/1/2 |

- 提交前 `validateDraft` 遍历所有草稿字段复用同一套 `validateField` 兜底。
