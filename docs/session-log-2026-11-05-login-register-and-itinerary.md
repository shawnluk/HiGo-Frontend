### 1. 配色

- 背景：蓝紫粉渐变 → 暖白浅红 `#fff5f2 → #fffaf8`，装饰光斑改为红/橙/珊瑚。

- 输入框浅灰底 + 中性内阴影，占位符 `#b0b0b5`；主按钮红色渐变。
- 提示文案 `#999999`，底部提示整体水平居中。

### 2. 双登录方式

- 默认：用户名 + 密码。
- 手机号 + 验证码：

  - 验证码输入框右侧「获取验证码」，校验手机号后进入 60 秒倒计时；
  - 提示文案「未注册的手机号将自动创建账号～」。
- 切换入口位于「出发！」按钮上方：登录页显示「手机号登录 › / 账号密码登录 ›」；注册模式不显示。
- `👋` 移至「欢迎回来」左侧，同行垂直居中，字号 52rpx 与标题一致。

### 3. 其他登录 / 注册方式

- 登录页：「其他登录方式」下方两个入口
  - 手机号（浅红圆底 + 红色电话图标）→ 点击切到手机号验证码表单；
  - 微信（绿色圆底 + 白色微信图标）→ 点击提示「微信登录功能待接入」。
- 注册页：「其他注册方式」下方仅微信入口，点击提示「微信注册功能待接入」。
- 协议勾选：
  - 在「登录即同意《用户协议》和《隐私政策》」文字前新增圆形勾选框，默认未勾选；
  - 未勾选点击「出发！/注册！」提示「请先勾选并同意协议」；
  - 注册模式下文案自动变为「注册即同意」。
- 顺序：出发按钮 → 协议勾选 → 其他登录/注册方式 → 底部提示文案。

### 4. 注册表单可选字段

- 在「确认密码」下方新增两行：
  - 「手机号（可选）」，`+86` 前缀，`maxlength=11`；
  - 「验证码（可选）」，`maxlength=6`，右侧「获取验证码」按钮与 60 秒倒计时。
- 两个字段与手机号登录复用 `form.phone` / `form.code`。
- 注册提交时手机号随请求发送；验证码仅界面预留，未提交、未校验。

### 5. 密码规则与提示

- 长度 **6–10 位**。
- 仅允许：中文、大小写字母、数字、下划线 `_`、连字符 `-`。
- 禁止：空格、Emoji、其他标点。
- 前端在注册提交前校验并 Toast 提示；注册模式密码框下方常驻提示文案：
  「密码需 6-10 位，仅支持中文、字母、数字、下划线和连字符」。
- 后端同步校验，错误信息为：
  - `密码长度需为 6-10 位`
  - `密码只能包含中文、字母、数字、下划线和连字符`

### 6. 密码可见按钮

- `👁 / 🙈` emoji 替换为 `uni-icons`：隐藏时 `eye`、明文时 `eye-slash`，颜色 `#999999`、20px，保留 64rpx 点击热区。

## 六、注册接口（后端）

### 1. 现状与改造

原接口只接收 `username`、`password`（可选 `nickname`、`avatar`）。现扩展为：

- 请求字段：`username`、`password`、可选 `phone`、`nickname`、`avatar`。
- 校验：
  - 用户名非空；
  - 密码 6–10 位且字符集符合规则；
  - 手机号可选，填写时需匹配 `/^1[3-9]\d{9}$/`；
  - 用户名重复 → 409「用户名已存在」；
  - 手机号重复 → 409「手机号已被注册」；
  - 上述错误均为中文提示，可直接被前端 Toast 展示。
- 写入：`users` 增加 `phone` 字段；返回体增加 `phone`、`user_no`。

### 2. 顺带修复：注册必然 500

`user_profiles` 表中 `user_no`、`last_login_time`、`update_time` 为 `NOT NULL` 且无默认值，原插入语句缺少这些字段，导致 `users` 写入成功但资料表失败、接口返回 500，并留下孤儿用户记录。

修复后：

- 生成业务编号 `U` + `user_id` 左补零到 6 位（如 `U000023`）；
- `INSERT_USER_PROFILE` 写入 `user_id`、`user_no`、`nickname`、`avatar`，并用 `NOW()` 填充 `last_login_time`、`register_time`、`update_time`。

### 3. 验证

在临时端口 `3100` 启动后端验证（测试数据已清理）：

- 携带 `phone` 注册成功，返回 `user_id` / `user_no` / `phone`；
- 短密码、非法手机号分别返回中文 400；
- 重复用户名、重复手机号返回 409；
- 注册后使用用户名密码登录成功，资料正常返回；
- 已验证用户表 `phone` 字段可写入，`user_profiles` 记录完整。

> 注意：本地 3000 端口进程需重启后才会加载新代码。

### 2. 页面结构（对齐 `unitone-ui/行程.png`）

- 页面底色 `#f5f5f7`，左右内边距 28rpx。
- 顶部：圆形返回按钮 + 「行程」56rpx 大标题 + 右侧圆形筛选按钮（三条横线，自绘）。
- 状态 Tab：浅灰胶囊轨道，激活项红色 `#ff3b30` 胶囊 + 白字，切换即筛选。
- 星期条：横向滚动，周一至周日，默认选中今天；选中项红底白字。

  - 左列时间；
  - 中间圆点 + 竖线（待开始为红色空心圆，已结束为灰色实心）；
  - 右侧卡片：封面渐变、标题（最多两行）、价格徽标（付费粉底 / 免费紫底 / 已打卡灰底）、地点行（红色定位图标 + 报名人数）、「来自·圈名」。
- 空状态：白卡片「这一天暂时没有行程 / 行程数据（待接入）」。

### 3. 待接入标注

- 筛选按钮点击 → 「行程筛选功能待接入」；
- 行程卡片点击 → 「行程详情待接入」；
- 区块标题右侧 → 「（待接入）」；
- 空状态副标题 → 「行程数据（待接入）」。

### 4. 返回逻辑

- 有页面栈：`uni.navigateBack()`；
- 无页面栈：`uni.reLaunch({ url: '/pages/index/index' })`。

### 5. 未加底栏说明

参考图底部是自带「行程」Tab 的主导航。当前 App 自定义底栏为「活动 / 时刻 / 发布 / 消息 / 我的」，行程是从「我的」进入的子页面，因此未引入 `bottom-tab-bar`，避免出现不存在的 Tab 或错误高亮。
